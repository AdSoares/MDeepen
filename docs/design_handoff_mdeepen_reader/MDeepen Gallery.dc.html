Data Flow

A write request is validated synchronously, appended to the log, and acknowledged. All heavy work happens asynchronously downstream of the commit.

The client never waits on fulfillment. Once the order.created event is committed, a 202 is returned and downstream projections react on their own schedule.

This lag between commit and projection is why GET /orders/:id can briefly return a stale status under load.

Error Handling

Failures are classified as retryable or terminal. Retryable failures re-enter the queue with exponential backoff; terminal failures move to the dead-letter topic and page on-call. A message that fails five times is quarantined, not dropped.

Explanation BeginnerIntermediateExpert

Retryable failures are transient — the system waits, doubling the delay each time (exponential backoff), and tries again. Terminal failures can never succeed on retry, so they're routed to a dead-letter queue for a human to inspect.
